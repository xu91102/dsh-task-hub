# Agent Note: Task Hub 智能体会话

Status: implemented

## Problem

Task Hub 需要持久化用户创建的智能体身份，而 DeepSeek Harness 负责模型选择、工具、提示词区段、Skill、会话日志和执行。若混淆两类职责，任务面板会持久化部署细节，或创建没有所选运行时的会话。

任务审核通知的生命周期也长于任务的 `in_review` 状态。如果用户接受或退回任务时删除通知，同一操作将无法继续记录已读和归档状态。

## Decision

`AgentProfile` 保存用户的稳定展示身份、指令、并发数、可见性和所选 Harness preset id。HTTP 调用方通过原始 JSON 进入服务，因此服务会在持久化前验证部署可变的数值和枚举字段。每次任务执行都会创建独立、持久化的 Harness 会话。创建会话时先解析当前模型和所选 preset，再发布智能体；未发布的 setup 会安装完整模型选择并挂载 preset。缺少或无效的引用会直接失败，不会发布会话。

智能体和任务 Builder 会话使用同一条创建路径。仅当用户确认建议配置后，会话级工具才会持久化智能体资料或任务。初始用户消息、工具调用和工具结果均保留在 Harness 会话日志中。

审核收件箱事件由追加写入的任务状态活动投影得到。活动 id 作为事件身份，活动记录同时保存进入审核状态的 execution id。因此接受、退回或让同一次执行再次进入审核都不会删除或覆盖事件。已读和归档回执作为独立的持久化状态保存。

浏览器插件使用 Harness 对话视图打开 Task Hub。发布版宿主包尚未暴露所需扩展槽和导航元数据，因此本包的 postinstall patch 只补充这些位置。打开某次执行时，插件先选择对应的 Harness 会话，再选择 `chat` 对话视图。

## Alternatives considered

**在 `AgentProfile` 中持久化完整运行时配置。** 这种方式会复制 Harness preset 组合，并在 preset 变化后失效。因此资料只保存 preset id，每次新建会话时重新解析。

**先创建会话，再报告 preset 或模型错误。** 这会发布无法完成组装或执行的对话。解析和挂载保留在未发布的智能体创建阶段，失败会在会话可见前回滚。

**只按任务当前状态派生审核事件。** 接受和退回会移除 `in_review`，导致事件在回执更新前消失。追加写入的状态活动可保留事件，同时避免引入第二套事件内容存储格式。

**替换完整宿主客户端包。** 分叉完整客户端会使插件接管无关 UI 行为。小型 patch 脚本只添加 Task Hub 使用的扩展点，并在预期的上游锚点变化时失败。

## Consequences

删除或破坏所选 preset 会立即阻止新的 Task Hub 会话，而已有会话继续使用启动时的组合。用户资料可以独立于会话历史持久化和编辑。

只要任务多次进入审核状态，收件箱历史就可包含多条审核事件。每条事件拥有独立回执，并保留该次状态转换关联的执行会话。

升级宿主客户端后，安装前必须运行 patch 契约测试。本包会验证会话创建、preset 失败回滚、任务与智能体 Builder、持久化收件箱事件、精确会话跳转和组装后的浏览器流程。可运行的无密钥示例通过真实 agent loop 驱动 Builder，并记录其模型可见提示词、挂载的 preset、工具 schema、工具结果和最终回复。
